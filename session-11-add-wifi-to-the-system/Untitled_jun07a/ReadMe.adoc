# Session 11 – WiFi, HTTP GET & POST with ESP32

## Overview

In this session, I learned how to connect a real ESP32 board to WiFi using Arduino IDE and how to send and receive data over the internet using HTTP requests.

The project combines:

* ESP32 WiFi connection
* HTTP GET request
* HTTP POST request
* JSON data format
* ArduinoJson library
* FreeRTOS tasks
* Sensor data sending
* BLE notifications

---

## Hardware and Environment

This project was tested on a real ESP32 board using Arduino IDE.

WiFi credentials are defined in the code:

```cpp
const char* WIFI_SSID = "ZONG MBB-E5573-24A2";
const char* WIFI_PASSWORD = "********";
```

> The real WiFi password should not be uploaded to GitHub.
> A placeholder should be used instead.

## What I Learned

### WiFi Connection

The ESP32 connects to a WiFi network using:

```cpp
WiFi.begin(WIFI_SSID, WIFI_PASSWORD);
```

Before sending HTTP requests, the code checks:

```cpp
WiFi.status() == WL_CONNECTED
```

---

### HTTP Protocol

HTTP is used for communication between a client and a server.

In this project:

* The ESP32 is the client
* The server receives or sends data
* The ESP32 sends requests and reads responses

---

### GET Request

A GET request is used to receive data from a server.

Example endpoint:

```text
http://api.open-meteo.com/v1/forecast?latitude=32&longitude=34&current_weather=true
```

The response is returned in JSON format.

The code parses the response and prints weather data such as:

* current temperature
* wind speed

---

### POST Request

A POST request is used to send data to a server.

Example endpoint:

```text
http://httpbin.org/post
```

The ESP32 sends sensor data as JSON.

Example JSON:

```json
{
  "reading_id": 1,
  "temperature": 25.1,
  "humidity": 60.2,
  "distance": 30.5,
  "device": "RoboGreeno-ESP32"
}
```

## FreeRTOS Tasks

The project uses FreeRTOS in order to run several actions at the same time.

---

### sensorTask

This task reads the sensor values every 2 seconds.

It updates the global variables:

```cpp
g_temp
g_hum
g_distance
```

---

### wifiTask

This task sends the sensor data to the server every 5 seconds using HTTP POST.

The WiFi task uses a larger stack size:

```cpp
8192
```

WiFi and HTTP operations need more memory than simple sensor tasks.

---

### displayTask

This task prints the current data to the Serial Monitor.

It displays:

* temperature
* humidity
* distance
* WiFi status
* POST status

---

### bleTask

This task sends the latest sensor data using BLE notify.

The BLE task uses:

```cpp
4096
```

as its stack size.

## Important Notes

### Real ESP32 WiFi

This project runs on a real ESP32 board.

Example structure:

```cpp
const char* WIFI_SSID = "YOUR_WIFI_NAME";
const char* WIFI_PASSWORD = "YOUR_WIFI_PASSWORD";
```

For GitHub, the real password should be replaced with:

```cpp
const char* WIFI_PASSWORD = "********";
```

---

### Wokwi WiFi

If the project is tested in Wokwi, the default WiFi credentials are:

```cpp
const char* WIFI_SSID = "Wokwi-GUEST";
const char* WIFI_PASSWORD = "";
```

---

### Always Check WiFi Status

Before every HTTP request, the code checks:

```cpp
if (WiFi.status() == WL_CONNECTED)
```

This prevents HTTP requests from running when WiFi is not connected.

---

### Always Call http.end()

After every HTTP request, the code calls:

```cpp
http.end();
```

This frees resources and prevents memory problems.

---

### Use Correct Content-Type

For POST requests with JSON, the code adds this header:

```cpp
http.addHeader("Content-Type", "application/json");
```

## Common Problems

### WiFi Stuck on Connecting

If the Serial Monitor prints many dots like this:

```text
WiFi Connecting................................
```

possible causes are:

* wrong WiFi name
* wrong WiFi password
* the network is not 2.4GHz
* the ESP32 cannot see the network
* another connection method is running at the same time

---

### ArduinoJson Error

If this error appears:

```text
ArduinoJson.h: No such file or directory
```

the ArduinoJson library must be installed from the Library Manager.

---

### HTTPClient Error

Correct usage:

```cpp
#include <HTTPClient.h>

HTTPClient http;
```

Wrong usage:

```cpp
HttpClient http;
```

`HTTPClient` is the ESP32 HTTP client library.

---

### Arduino Cloud Conflicts

If the project uses Arduino Cloud, `thingProperties.h` may already define names such as:

```cpp
SSID
PASS
temp
hum
distance
```

To avoid conflicts, the main code uses different names:

```cpp
WIFI_SSID
WIFI_PASSWORD
g_temp
g_hum
g_distance
```
